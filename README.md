# Secure Student Portal (Lab 5 target app)

Python 3.11+ and Flask, single file `app_secure.py`. It implements the four user stories from Lab 1 and the
trust boundaries from Lab 2: login, assignment upload, lecturer messaging, profile update (plus grades and attendance).

## Run it
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python app_secure.py initdb          # creates the database and 4 demo users; passwords are random and printed once
flask --app app_secure run           # http://127.0.0.1:5000
```
First login: enter username and password, then scan the QR code with an authenticator app (MFA is mandatory for every user).
Demo users: students `alice`, `bob`; lecturers `dr.chen` (CT101), `dr.kumar` (CT102).

## Lab 5 Step 1 check (also automated)
```bash
python -m unittest discover -s tests -t .       # 18 tests, ~15 s
```
Valid login, generic wrong-login error, allowed upload types, messaging, and "profile update only edits the logged-in user" are each a test.

## Lab 5 Step 2: Semgrep (SAST)
```bash
pip install semgrep
semgrep scan --config auto . --exclude .venv --exclude instance --json -o semgrep-results.json
```

## Lab 1 / Lab 2 control map (ASVS IDs as used in your labs)
| Story / boundary | Threat (ATT&CK) | Control | Where in `app_secure.py` |
|---|---|---|---|
| 1 Login, TB01 | T1110 | Argon2 hashes, 12-char policy, lockout after 5 failures for 15 min, CAPTCHA after repeated failures, IP rate limit (6.3.1, 6.4.1, 6.2.1) | `login`, `register_failure`, `check_password_policy` |
| 1 Login | T1589 | One generic error, dummy hash so timing is equal, same response for locked accounts (4.2.1) | `login` |
| 1 / 4 / TB05 | T1078 | Mandatory TOTP, single-use codes, breached/common-password check (6.3.3, 6.2.12) | `mfa`, `verify_totp`, `COMMON_PASSWORDS` |
| 2 Upload, TB02 | T1190, T1105 | Extension allow-list, magic bytes, 5 MB cap, malware scan (EICAR + optional ClamAV, fails closed), random names outside static, attachment download (5.2.x, 5.3.x, 5.4.3) | `validate_upload`, `assignments`, `download` |
| 3 Messaging, TB05 | T1566 | Output encoding, only http/https links (1.2.1, 1.2.2); lecturer can message only own students; only sender/recipient can read (8.2.2) | `linkify`, `message_new`, `message_view` |
| 4 Profile, TB02 | T1190, T1078 | Re-enter password to save (7.5.1), server-side field allow-list, user id from session only (8.2.2, 8.2.3, 8.3.1) | `profile` |
| All, TB03 | T1190 | Parameterised SQL only | every `execute` call |
| All | Repudiation | Timestamped, user-attributed audit table | `audit` |
| All | Info disclosure | Generic error pages, CSP, nosniff, no-store, secure cookies | `register_hooks` |

## Known limits (say these in the report)
* CAPTCHA is a simple arithmetic challenge so the project runs offline; production should use reCAPTCHA or hCaptcha.
* Breached-password check is an offline list; production should query a breach corpus (for example the HIBP range API).
* The TOTP secret is stored unencrypted in SQLite; production should encrypt it or use an identity provider (Lab 2 TB04).
* Email gateway, cloud storage and identity provider from the Lab 2 DFD are not integrated; files go to local disk.
* Students cannot reply to messages (user story 3 is lecturer to student only).
* No self-service password reset: a lecturer or administrator workflow is out of scope.
* Dev mode runs over HTTP. Set `PORTAL_ENV=prod` behind TLS (secure cookies and HSTS), and run with gunicorn, not `flask run`.
* ASVS control IDs follow your lab tables; check them against the ASVS 5.0 text before you submit.

## Security Testing
This repository is configured to run Semgrep automatically using GitHub Actions
(`.github/workflows/semgrep.yml`). Every push or pull request to `main` triggers a scan of the
whole repository. The results are saved as JSON and text, and a Markdown summary is generated by
`semgrep_report.py`. All three files are uploaded as the `semgrep-results` artifact of the run.
